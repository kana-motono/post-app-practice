# テストの決まり

## 進め方

- 実装を頼まれたら、テストも書く。
- `./vendor/bin/sail test` で全テストを回し、落ちたら通るまで直す。
- 1クラスだけ回すときは `./vendor/bin/sail test --filter ReplyTest` のようにする。
- 最後に、実行したコマンドと結果（通った件数・落ちたテスト）を報告する。回せなかった場合は、回せなかったと理由を書く。

## 置き場所と土台

- 機能のテストは `tests/Feature/<機能>Test.php` に置く（例: `PostCreateTest`、`ReplyTest`）。`tests/Unit/` は使っていない。
- クラスは `Tests\TestCase` を継承し、`use RefreshDatabase;` を付ける。DB は `phpunit.xml` の MySQL `testing` データベースで、SQLite やインメモリではない。
- `setUp()` で User・Category・Post を作り、プロパティに持つ。ユーザーには `name` を日本語で付ける（例: `投稿者A`、`別の人`）。
- 繰り返す準備や送信は、クラス内の private ヘルパーにまとめる（例: `makePost`、`makeReply`、`sendReply`）。ログインは `actingAs` で行う。

## 書き方

- テスト名は `test_` + 日本語で、「何をしたらどうなるか」が分かるようにする（例: `test_141字だとエラーになりポストは増えない`）。コメントも日本語。
- 受け入れ条件があるときは、条件ごとにコメントで区切って並べる（`// 受け入れ条件1: …`）。条件がないときは `// ---- 正常系 ----` のように、正常系・異常系・表示の出し分け・回帰で区切る。
- 並び順のテストは、作成順と逆の `created_at` を `forceFill` で付け、日時で並んでいることを確かめる。同時刻は id 順になることも確かめる。

## 入力チェックのテスト

入力項目ごとの仕様に応じて、次を書く。

**140字制限のある入力項目（ポスト本文・リプライ本文）だけ**

- 境界: 140字ちょうどは通り、141字はエラーになる。
- 改行: ブラウザ由来の CRLF は1字として数える（`"あ\r\n"` を送る）。
- 残り文字数が画面に出る項目は、エラーで戻ったときも残り文字数が残る。

**各入力項目の仕様に応じて**

- 空・空白だけ・項目自体がない場合。
- 配列など文字列でない値を送っても 500 にならず、エラーになる。
- エラーメッセージの日本語の文言を `assertSessionHasErrors` で確かめる。
- エラーのときは、保存も更新もされない（`assertDatabaseCount`、`->fresh()` で確かめる）。
- エラーで戻った画面に、メッセージと入力済みの内容が残る。

## 認証・認可・存在しないもの

- 未ログインは `assertRedirect(route('login'))`。件数が変わっていないことも確かめる。
- 投稿者以外の編集・削除は `assertForbidden()`（403）。画面では、編集・削除ボタンが本人にだけ出ることを `assertSee` / `assertDontSee` で確かめる。
- 存在しないポスト・リプライは 404。
- 投稿者は常にログイン中のユーザーになる（リクエストの `user_id` を送っても無視される）。

## 回帰

- 既存の動き（一覧の並び、タイトルから詳細へのリンク、編集・削除ボタンの出し分け、削除時のカスケード）を変える変更では、変わっていないことを確かめるテストを足す。`ReplyTest` の「回帰（変えないもの）」を参考にする。
